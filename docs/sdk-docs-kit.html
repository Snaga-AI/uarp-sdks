Everything the docs need to say about the UARP SDKs

Five client libraries are published and installable today. This is the material to turn into pages: what to install, what the first call looks like in each language, the behaviour that is the same everywhere, and the four things that will mislead readers if they are left out.

One OpenAPI document generates all five, so the surface is identical: every endpoint and every model is present in every language, and they were checked against each other and against the live API before release.

Installing, and the first call

Each block below is a complete first page for that language. The API key falls back to UARP_API_KEY, then SNAGA_API_KEY; the base URL falls back to UARP_BASE_URL, then production.

TypeScriptnpm · ESM only
npm install uarp-sdk
import { UarpClient } from 'uarp-sdk';

const client = new UarpClient({ apiKey: process.env.UARP_API_KEY });

const agent = await client.agents.create({ name: 'quickstart' });

for await (const item of client.agents.listAll({ limit: 100 })) {
  console.log(item.name);
}

Behaviour that is the same in all five

Worth one shared page rather than repeating per language. The examples are TypeScript; every other SDK does the same thing in its own idiom.

Authentication

A bearer key, uarp_<prefix>_<secret>, passed explicitly or read from the environment.

Idempotency and retries

Every mutating /api/v1/* call carries an Idempotency-Key, which is also what makes a write safe to retry. Transient failures — 408, 409, 429, 500, 502, 503, 504, dropped connections — are retried with full-jitter backoff, honouring Retry-After and the X-Should-Retry: false opt-out. Reads always retry; writes only when they carry a key. Callers can supply their own key to replay a create deliberately.

Errors

RFC 9457 problem documents become typed errors carrying the status, title, detail, correlationId and any field-level validation failures.

try {
  await client.agents.get(id);
} catch (error) {
  if (error instanceof APIError) {
    console.error(error.status, error.problem.title, error.problem.detail);
  }
}

Streaming

The eleven SSE endpoints return a native async type that reopens with Last-Event-ID when a connection drops. A connection that delivered at least one event earns a fresh reconnect budget, so a flapping server cannot spin the loop.

for await (const event of client.runs.streamRunEvents(runId)) {
  if (event.event === 'run.completed') break;  // leaving the loop closes the request
}

Pagination

Paginated endpoints get a second method that walks every page and yields items.

for await (const agent of client.agents.listAll({ limit: 100 })) { /* … */ }

Forward compatibility

An enum value the API adds tomorrow decodes into the existing type rather than failing, so an SDK release does not have to chase every new status or kind.

Per-call overrides

Timeout, retry budget, idempotency key and extra headers can be set for a single call. Four SDKs take them as a trailing argument. Rust has no default arguments, so they ride on a cheap clone of the client that shares its connection pool: client.with_timeout(..).agents().get(id).

Four things the docs must say

Each of these has already caught someone out. Leaving any of them implicit turns a five-minute integration into an afternoon.

TypeScript is ESM only.

import works everywhere. require('uarp-sdk') needs Node 22.12 or newer, where Node learned to require an ES module; below that a CommonJS caller has to use await import('uarp-sdk'). The floor for the package itself is Node 18.

Kotlin consumers need Kotlin 2.2.

The library is built with 2.2, and Kotlin's binary metadata is not readable by older compilers: a project on 2.0 fails with "Module was compiled with an incompatible version of Kotlin" before it reaches any of the API. This is not a runtime requirement — it stops the build.

Swift event streams are Apple-only.

The package builds on Linux and all 557 request/response operations work there, but the eleven streaming endpoints do not: URLSession.bytes is missing from swift-corelibs-foundation, and every other way of reading a response on that platform buffers it to completion — which never happens on a stream that stays open. Calling one on Linux throws UARPError.stream with that explanation.

JavaScript cannot hold integers past 253.

If the API ever returns one, the TypeScript SDK silently loses precision — a JavaScript number is a double. No endpoint sends one today. Worth a line in the reference rather than a surprise later.

Suggested page structure

  1. Client libraries — the table above, with install lines. One page.
  2. Getting started, one page per language — install, authenticate, first call, first stream. The blocks above are ready to lift.
  3. Behaviour — one shared page for authentication, idempotency, retries, errors, streaming, pagination and overrides, with tabs per language rather than five near-identical pages.
  4. Reference — link out to the generated documentation each ecosystem already hosts: docs.rs for Rust, the npm page for TypeScript, javadoc.io for Kotlin. Do not hand-write it; it is generated and will drift.
  5. Limits — the four caveats, stated once, linked from each getting-started page.

Where things are

  • Source, issues and the changelog: Snaga-AI/uarp-sdks. Every release is described there; the changelog is the place to check before writing about a version.
  • Swift consumers point at Snaga-AI/uarp-swift, which is a mirror. Issues belong in the main repository.
  • Each package has its own README with the fuller treatment of streaming, pagination, error handling and the escape hatch for calling an endpoint by hand.

The version is shared: all five are cut from one tag, so 0.3.0 means the same surface everywhere. When one moves, they all move.
